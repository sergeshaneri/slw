# Идеи для расширения TG-уведомлений SLW

> Карта возможных направлений развития нотификаций. Текущая
> реализация (2026-05): 3 типа в ежедневном scheduler'е + админ-broadcast
> + per-user message. Здесь — что ещё можно добавить.

---

## 1. Новые триггеры (когда отправлять)

### Жизненный цикл юзера
- **Утреннее настроение** — 8:00 МСК, если есть `user_habits`.
  «Доброе утро. Сегодня твоя практика «утренний скан тела» — 5 минут. Открыть?»
- **Стрик ломается** — 22:00 МСК, нет активности сегодня, `streak ≥ 3`.
  «Стрик 5 дней. До конца дня хватит одной записи в дневник.»
- **Стрик восстановлен** — событие, сразу после возобновления.
  «Стрик 1. Снова стартуем 🌱»
- **Долгий простой** — `last_active_at` > 7 дней.
  «Прошла неделя. Мы тут, без давления. Если хочется — открой.»
- **Достигнут уровень** — событие, сразу после R-2 (закрытие L0/L1/L2).
  «Закрыл L0 в ЧЭ. Следующий — L1 «Карта целей». Открыть?»
- **Достижение разблокировано** — событие, после grant_achievement.
  «🏆 «Первая запись» — за первую запись в дневнике.»

### Прогресс по контенту
- **Новые анкеты доступны** — открылся новый уровень с не пройденными surveys.
  «На L1 ЧЭ открылось 6 новых навыков для оценки.»
- **Завтра событие из дневника** — у юзера в notes есть «завтра X».
  «Завтра у тебя «собеседование» — попробовать «Скан желания»?»
- **Insight-streak** — 7 дней подряд писал инсайты.
  «7 дней подряд с инсайтами 🔥 Какой паттерн заметил за неделю?»

## 2. Социальные (event-driven, сразу)

- **Реакция на твой инсайт** — приходит любая reaction (heart/aha/fire/thanks).
  «Кто-то реагирует 🔥 на твой инсайт по ЧЭ. Открыть?»
- **Новый подписчик** — кто-то follow'нул.
  «У тебя новый подписчик: Иван. Открыть профиль?»
- **Личное сообщение (DM)** — новое сообщение в DMView.
  «Иван написал тебе. Открыть?»
- **Ответ на твой вопрос в холле** — новый answer к твоему question.
  «Аня ответила на твой вопрос в холле БС.»
- **Лучший ответ** — кто-то отметил твой ответ как best.
  «Твой ответ выбрали лучшим в холле ЧЭ. +3 XP.»

---

## 3. Аналитика и инсайты

- **Недельный отчёт** — воскресенье 19:00.
  «За неделю: 12 шагов, 5 инсайтов, +120 XP. Открыть аспект, который больше всего вырос?»
- **Месячный итог** — 1-е число утром.
  «Итоги месяца: твой главный рост в ЧИ (+1.8). Подробнее?»
- **Аспект-чемпион** — раз в неделю, самая активная сфера.
  «Самая активная сфера за неделю — БС. Возьми за ось.»
- **Аспект-отстающий** — раз в неделю.
  «Самая забытая сфера — БЭ. 0 шагов за 2 недели. Заглянем?»
- **Доминирующая эмоция** — раз в неделю по `emotions`.
  «На этой неделе у тебя 4 раза была «тревога» с интенсивностью ≥ 7. Записать ещё одну рефлексию?»

---

## 4. Геймификация

- **Стардаст-бонус** — за редкое событие. «+5 ✦ за стрик 7 дней.»
- **До следующей ачивки X шагов** — когда близко.
  «До «Карта 8 планет» осталось открыть 2 аспекта.»
- **Челлендж дня** — утро, опционально.
  «Челлендж дня: открой случайный аспект и пройди 1 шаг.»
- **Сравнение с собой** — раз в неделю.
  «На этой неделе ты прошёл столько же шагов, сколько за всю прошлую. ⬆️»
- **Попадание в ТОП-N** — при попадании в leaderboard.
  «Ты в ТОП-10 по XP за неделю. Глянуть позицию?»

---

## 5. Контент-фичи

- **Слово дня** — утром 9:00. «Слово дня — «Тонус». Что для тебя сегодня тонус?»
- **Цитата дня** — утром 9:00. «"Гермес: …" Какой твой ответ?»
- **Случайный аспект на разведку** — раз в неделю.
  «Сегодня предлагаю заглянуть в ЧИ — мир идей и возможностей. 1 шаг = 5 мин.»
- **Новая статья / подкаст** — broadcast при появлении контента.

## 6. Контроль качества (анти-спам)

### Уровень платформы
- **Quiet hours** — не слать с 23:00 до 8:00 даже broadcast.
  Хранить в `NotificationSettings.quiet_hours_start/end`.
- **Лимит N сообщений в день на юзера** — например, не более 2.
  Считать по `notification_log`.
- **Per-type subscriptions** — в Settings чекбоксы для каждого типа,
  не только глобальный. Поле `web_users.notification_types JSONB`.

### Уровень юзера
- **DND-режим на N дней** — `/pause 7d` в боте → `pause_until` в БД.
- **Snooze в сообщении** — inline-кнопка «Напомни завтра» (callback) на
  каждом уведомлении.
- **Per-user timezone** — поле `web_users.timezone`, рассылать в его 18:00
  локально, а не в общее UTC-время.
- **Кнопка «Не показывать этот тип»** в TG-сообщении (callback).

## 7. Расширения Broadcast

### Сегментация
- **По аспекту** — «Только тем, у кого ЧЭ ≥ L1»
- **По статусу** — «Только новички < 3 шагов» / «Только активные» / «Только спящие 7+ дней»
- **По дате регистрации** — «Только зарегистрировавшимся за последние 7 дней»

### Форматирование
- **Markdown / HTML в TG** — поддержка через `parse_mode='HTML'`
- **Inline-кнопки в broadcast** — кастомные ссылки и действия
- **Изображение / стикер** — прикрепить картинку к broadcast'у
- **Голосовое уведомление** — `bot.send_voice` записанным сообщением

### Управление
- **Запланированные broadcast'ы** — таблица `scheduled_broadcasts`.
  «Отправить завтра в 12:00.»
- **Шаблоны** — сохранённые тексты для повторяемых анонсов.
- **A/B-тестирование** — два варианта текста, ротация, в логе видно где
  больше открытий.
- **Preview перед отправкой** — кнопка «👁 Предпросмотр» показывает как
  будет выглядеть в TG.

## 8. Telegram-возможности

### Engagement-трекинг
- **Кнопка «Открыто 👀»** — callback button. В `notification_log`
  считаем CTR (click-through rate) per type.
- **Реакции на бот-сообщения** — юзер может отреагировать ❤️🔥🤔,
  считается фидбэком.

### Интерактив
- **Inline-вопрос** — «Как настроение сейчас? 😊😐😢». Кнопки сразу
  пишут в `emotions` таблицу через webhook callback.
- **Quick-actions** — «Записать инсайт» прямо из TG → бот спросит текст,
  сохранит в дневник без открытия Mini App.

## 9. Админка-плюшки

### Визуализация
- **График отправок за 30 дней** — sparkline: сколько в день, сколько ошибок
- **CTR per type** — процент кликов на «Открыть приложение» из каждого типа
- **Heatmap по часам/дням** — когда юзеры реагируют чаще

### Управление юзерами
- **Таблица «Статус юзеров»**:
  - Получают: подходят под условия, не отписались
  - Отписались: notifications_enabled=false
  - Заблокировали бота: помечены автоматически при Forbidden
  - Без TG: нет telegram_id
- **Per-user история** в UserDetail — «Уведомления этого юзера» (последние N)
- **Симуляция рассылки (dry-run)** — «Кому бы сейчас отправили и какой тип» —
  без реальной отправки. Используется для предпросмотра перед run-now.

### Отладка
- **Лог с фильтром** — по типу, юзеру, ошибке, дате
- **Re-send ошибочных** — кнопка «Попробовать снова отправить» для записей с error
- **Test broadcast одному юзеру** — отдельный режим: ввести user_id, текст, увидеть результат

## 10. Приоритетный порядок реализации (мой взгляд)

Если делать по value-добавке, то так:

### Фаза 2 — «Не бесить» (короткая)
- Quiet hours (нельзя слать с 23 до 8)
- Per-type subscriptions в Settings
- Symuляция (dry-run) перед `run-now`
- Кнопка «Снузить на завтра» в каждом сообщении

### Фаза 3 — «Живой бот» (event-driven)
- Реакции на инсайт → уведомление
- Новый подписчик → уведомление
- DM → уведомление (опционально, есть PUSH)

### Фаза 4 — «Аналитика и ценность»
- Недельный отчёт по воскресеньям
- Аспект-чемпион / отстающий
- Доминирующая эмоция

### Фаза 5 — «Геймификация»
- Стрик ломается / восстановлен
- Достижение разблокировано
- Челлендж дня

### Фаза 6 — «Богатая админка»
- Сегментация broadcast'ов
- A/B-тесты
- Запланированные broadcast'ы
- Шаблоны
- CTR-трекинг через callback кнопки

## Источники данных в БД (что уже есть)

| Что | Где |
|---|---|
| `last_active_at` юзера | `user_streaks.last_active_date` |
| Привычки | `user_habits` + `habit_ticks` |
| Pending tasks | `web_state.journey.aspects[X].pendingTasks` |
| Достижения | `web_achievements` (PK user+code) |
| Подписки | `subscriptions` (follower → target) |
| Реакции на инсайты | `insight_likes` |
| Ответы в Q&A | `aspect_messages` (kind='answer', parent_id) |
| Эмоции | `emotions` (date, name, intensity) |
| Тренировки | `trainings` |
| Журнал уведомлений | `notification_log` (новое, 2026-05) |
| Лидерборд | computed из `journey_events` + `completedScripts.length` |
