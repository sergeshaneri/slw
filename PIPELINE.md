# SLW-Mine — описание AI-пайплайна

> Личный AI-ассистированный пайплайн ведения дневника, выявления паттернов и месячной коучинг-аналитики, организованный вокруг **Соционического Колеса Баланса (СКБ)** — авторской системы из 8 аспектов соционики.
>
> Документ описывает текущее состояние пайплайна (апрель 2026) для возможной интеграции с веб-продуктом.

---

## 1. Кто пользователь и зачем

**Сергей** — практикующий духовный психолог. Ведёт ежедневный дневник как инструмент самонаблюдения, отслеживания паттернов, регуляции рутин и коучинговой саморефлексии.

Цели дневника:
- Осознанность (равномерное внимание к 8 сферам жизни)
- Отслеживание выполнения практик (трекеры разных периодов)
- Работа с эмоциями и повторяющимися паттернами
- Развитие самого пайплайна как продукта (мета-уровень)

Ценностные принципы:
- **AI не интерпретирует психологию** — именование инсайтов, уроков, корней эмоций — компетенция пользователя. AI структурирует, считает, сравнивает, спрашивает.
- **AI не додумывает** — если данных нет, ставит прочерк. Не генерирует «правдоподобные» цифры.
- **AI не оценивает** — никаких метакомментариев («хороший прогресс», «дисциплина»). Только факты.
- **Локальный приоритет** — данные хранятся локально (Obsidian-vault) и в личном репо на GitHub. Никаких облачных сервисов кроме GitHub и моделей через API.

## 2. Концептуальная модель: 8 аспектов СКБ

Дневник структурирован по 8 аспектам соционики (модель А Аушры Аугустинавичюте). Каждое событие/состояние/действие категоризируется в один или несколько аспектов:

| Код | Название | Сфера жизни |
|-----|----------|-------------|
| **БС** | Белая Сенсорика | Тело, комфорт, здоровье, быт, еда, сон, уход за пространством |
| **ЧС** | Чёрная Сенсорика | Воля, сила, тренировки, преодоление, статус |
| **ЧИ** | Чёрная Интуиция | Идеи, новый опыт, потенциал, инсайты, нестандартные решения |
| **БИ** | Белая Интуиция | Смысл, судьба, сны, предчувствия, духовный опыт, цикличность |
| **БЛ** | Белая Логика | Структура, знания, классификации, изучение, объективные системы |
| **ЧЛ** | Чёрная Логика | Дела, работа, проекты, доход, эффективность, результат |
| **БЭ** | Белая Этика | Отношения, близость, совесть, моральные оценки, доверие |
| **ЧЭ** | Чёрная Этика | Эмоции (вовне), энергия, экспрессия, «нравится/не нравится» |

Жёсткие правила (нарушать нельзя — иначе долговременная аналитика искажается):
- Тренировки → **ЧС**, не БС
- Быт/еда/сон → **БС**, не ЧЛ
- Общение/помощь друзьям → **БЭ**, не ЧЛ
- Работа/проекты/доход → **ЧЛ**
- Медицинское (даже если выглядит как «дело») → **БС**

Эти правила — продукт многих итераций; накапливаются в `skills/skb-coach-skill/learnings.md`.

## 4. Пайплайн — пять основных потоков

### Поток A: Сырой ввод → структурированный лог (ежедневно)

**Вход:** неструктурированный текст от пользователя — голосовая расшифровка, поток сознания, короткие заметки. Может быть хаотичным, без знаков препинания, с обрывками мыслей.

**Скилл:** [`skills/skb-coach-skill/SKILL.md`](skills/skb-coach-skill/SKILL.md) — алгоритм из 8 шагов:

```
0. Обязательное чтение (контекст, шаблон, аспекты, задачи, learnings)
1. Разбор входного текста (определение даты, временных блоков)
2. Категоризация по 8 аспектам (с aspects_quick.md как справочником)
3. Структурирование по template.md
4. Сверка с tasks.md (что выполнено)
5. Добавление новых задач (только если есть явный маркер «добавить задачу»)
5.5. Уточняющие вопросы при неопределённости
6. Самопроверка по чек-листу (1-е лицо, без додумывания, без метакомментариев)
7. Сохранение в diary/ММ.ДД день.md
8. Самообучение — добавление нетривиальных случаев в learnings.md
```

**Выход:**
- `diary/ММ.ДД день.md` — структурированный лог по `template.md`
- Возможные правки в `goals/tasks.md` (отметки выполнения, новые задачи)
- Возможные правки в `skills/skb-coach-skill/learnings.md` (новые правила категоризации)

**Структура одного лога** (`diary/04.24 пт.md` как пример):
- Метаданные (дата, общая энергия, сон)
- Мини-лог (утро/день/вечер/ночь — нарративные блоки)
- Глубокий лог эмоций (таблица для каждой значимой: эмоция, интенсивность 1-10, триггер, ощущения, корни, урок, что сделал)
- Тренировки (упражнения × подходы)
- Кофе-трекинг
- Очищение и здоровье
- Терапия и работа с собой
- Финансы (если есть движение)
- **Все 8 сфер** (Колесо Баланса) — таблица с заметками за день по каждому аспекту
- Рефлексия (победы, новые опыты, инсайты, вопросы к себе)
- Сводка регулярных практик

### Поток B: Самообучающаяся категоризация

`learnings.md` — ключевой механизм качества пайплайна. После каждой сессии, где AI неуверенно категоризировал событие или ошибся, добавляется правило в формате:

```
[YYYY-MM-DD] [пользователь], лог за [дата]:
- «[фрагмент текста]» → отнёс к [аспект]. Правило: [вывод в 1 предложение]
```

Примеры накопленных правил:
- «Поделился с близким про духовное» → БЭ (не БИ): рассказ о духовном содержании близкому = БЭ; личная сольная практика = БИ
- «Мама перевела деньги» → БЭ + финансы: мелкий перевод от близкого = жест отношений, не ЧЛ-доход
- «Бег в новом парке» → ЧС + ЧИ: тренировка в новом месте = одновременно волевое действие и новый опыт
- «Корневая эмоция, тряслась нога» → телесные ощущения остаются в поле «Ощущения» эмоциональной таблицы, НЕ в БС

Файл читается AI **в начале каждой сессии перед обработкой нового лога**. Свежие записи имеют приоритет.

### Поток C: Управление задачами

`goals/tasks.md` содержит:

1. **Ежедневный трекер** (Пн-Вс) — таблица 7 столбцов с регулярными практиками (йога, дневник, антипаразитарные, прогулка, чай). В конце недели архивируется.
2. **Еженедельный трекер** на 7 недель — практики уровня недели (полив цветов, пост для продвижения).
3. **Ежемесячный трекер** на 7 месяцев — задачи уровня месяца (стрижка, пылесос).
4. **Активные задачи по 8 сферам** — текущие приоритеты на каждую сферу СКБ с дополнительными чекбоксами.

Логи и задачи синхронизируются: после структурирования лога AI отмечает выполненное в `tasks.md` и предлагает архивировать законченные периоды.

### Поток D: Недельные аналитические отчёты

**Триггер:** запрос пользователя «сделай отчёт за неделю …».

**Промпт-спецификация:** `skills/review promt.md` (v2) — детальный шаблон с 12 секциями:

```
0. Заголовок + TL;DR callout (тема / сдвиг / красный флажок)
1. Дашборд (ключевые метрики таблицей)
2. Колесо Баланса (оценка 1-10 по 8 сферам + bar-чарт + прогресс-бары Unicode)
3. Главные темы периода (2-4 нарратива с аркой: начало → развитие → пик → текущее)
4. Highlights (победы / лучший момент / тяжёлый момент / срыв / новые опыты)
5. Привычки: streaks и обрывы (с bar-чартом по дням)
6. Эмоциональный ландшафт:
   6.1 Пики ≥8 (отдельный блок)
   6.2 Частотная таблица
   6.3 Позитив/негатив по дням (bar-чарт)
   6.4 Триггеры по крупным эмоциям
   6.5 Трансформации (что работало)
7. Тренировки (таблица + рекорды)
8. Прогресс по целям (светофор 🟢🟡🔴 для всех 8 сфер)
9. Финансы (отдельная карточка)
10. Красные флажки (повторяющиеся деструктивные паттерны)
11. 3-5 коучинговых советов (каждый: основание-цитата → эксперимент → метрика)
12. 7-10 вопросов для глубокой рефлексии
```

**Жёсткие правила формата:**
- Все цитаты с датами и wikilinks `[[ММ.ДД день]]`
- Только `bar`-чарты (эмпирически: плагин Obsidian Charts v3.9 не рендерит `radar` и `line` с 2+ series)
- Никакой психологизации в советах — только наблюдения и поведенческие эксперименты
- Метрики коучинговых советов измеримы

**Запуск:** AI читает все диарийные логи периода + tasks.md + learnings.md + промпт, делает подсчёты вручную, генерирует отчёт в `analytics/{start}-{end}.md`.

**Параллельная генерация:** для серии недельных отчётов запускается несколько AI-агентов параллельно — каждый получает свой период.

### Поток E: Месячный супер-отчёт + дашборд

**Триггер:** запрос «месячный синтез» / «суперотчёт».

**Источник данных:** не сырые логи, а 4 уже построенных недельных отчёта (синтез синтезов).

**Структура супер-отчёта** (`analytics/Месяц YYYY-MM-DD.md`):
- TL;DR месяца (главная арка / ключевой сдвиг / сквозной флажок / главная победа)
- Дашборд 4 недель бок о бок (метрики × недели + средние + тренды)
- Колесо Баланса — эволюция за 4 недели (одна радар-картинка с 4 слоями)
- Сквозные нарративы (3-5 арок, проходящих через 2+ недели)
- Highlights месяца (топ побед, пиков, тяжёлых моментов, срывов)
- Привычки: streaks/gap'ы за весь месяц
- Эмоциональный ландшафт месяца
- Тренировки — суммарные таблицы и рекорды
- Прогресс по целям (светофор итог)
- Финансы месяца
- Сквозные красные флажки (паттерны 2+ недель)
- Коучинговые выводы на следующий месяц (стратегические, не тактические)
- Вопросы рефлексии месячного уровня

**Финальная визуализация:** `analytics/dashboard.html` — single-file HTML-дашборд:
- 5 табов: Месяц + 4 недели
- Chart.js с CDN (radar для Колеса Баланса, bar для всего остального)
- Glassmorphism + неоновые акценты + анимированные счётчики
- Тёмная тема (фиолетово-индиго неон)
- Полностью клиентский, открывается двойным кликом в браузере
- Все цифры берутся из аналитических отчётов (трассируемость данных)

## 5. Данные и форматы

### Шаблон ежедневного лога (`templates/template.md`)

Markdown-документ со структурой из 11 секций (см. Поток A). Каждое поле — markdown-таблица или нарративный блок.

Эмоция фиксируется как таблица:
```markdown
| Поле | Значение |
|------|----------|
| Эмоция | <название> |
| Интенсивность | <1-10 или —> |
| Триггер | <что спровоцировало> |
| Ощущение | <как в теле> |
| Корни | <откуда взялось> |
| Урок | <чему учит> |
| Что сделал | <как трансформировал> |
```

### Формат имени диарийного файла

`ММ.ДД <короткий_день>.md` — например `04.24 пт.md`, `03.30 пн.md`. Дни недели по-русски: `пн вт ср чт пт сб вс`.

### Wikilinks между файлами

Obsidian-стиль `[[04.24 пт]]` → автоматический линк на файл лога. Используется во всех аналитических отчётах для трассировки цитат.

### Чарты в аналитике

JSON в codeblock `chart` (плагин Obsidian Charts):
```chart
{
  "type": "bar",
  "labels": ["..."],
  "series": [
    { "title": "...", "data": [числа] }
  ]
}
```
Без `null`, без `tension`/`fill`/`backgroundColor` (плагин не любит).

### Колесо Баланса — оценка 1-10

Для каждой сферы:
- 1-3: почти не тронута
- 4-6: эпизодическая активность
- 7-8: системная работа
- 9-10: фокус периода

Оценка вычисляется AI на основе количества упоминаний + качества активности + прогресса по целям. Не subjective — формализовано.

## 6. Технический стек

| Слой | Технология |
|------|-----------|
| **Хранилище** | Локальный Obsidian-vault (markdown-файлы) + Git/GitHub |

| **Воркфлоу** | Голос → расшифровка (вне пайплайна) → AI-структурирование → markdown |

## 7. Эмпирические ограничения и обходы

| Проблема | Обход |
|----------|-------|
| Obsidian Charts v3.9 не рендерит `radar` и `line` с 2+ series | В Obsidian-отчётах используется только `bar`. Радар-визуал колеса делается через bar-чарт + Unicode прогресс-бары `▓░` в таблице. В standalone HTML-дашборде radar работает (там Chart.js напрямую) |
| AI склонен додумывать инсайты | Жёсткое правило в `learnings.md`: «не уверен → прочерк» + чек-лист перед сохранением |
| AI генерирует метакомментарии («хороший прогресс») | Запрещено промптом + чек-лист самопроверки |
| Большие отчёты переполняют контекст агента | Делегирование в фоновые агенты с самодостаточными промптами; разбивка на недели |
| AI смешивает «изучение текста» и «духовный опыт» | Правило в learnings: чтение/информация = БЛ; молитва/практика = БИ |

## 8. Текущие пробелы

- **Нет автоматической суммаризации эмоций** в межнедельных трендах — каждый раз AI пересчитывает руками
- **Финансовый учёт неполный** — расходы фиксируются эпизодически, нет регулярного формата
- **Нет автоматических напоминаний** — AI запускается только по явному запросу пользователя
- **Голос → расшифровка** не интегрирована — пользователь сам приносит готовый текст
- **Нет мобильного интерфейса** — Obsidian + Git локально на десктопе
- **Чарты в Obsidian ограничены** (нельзя radar в нём) — приходится дублировать визуалы
- **Шаблон лога перегружен** — поля Финансы / Очищение почти не заполняются ежедневно

## 9. Что в этом пайплайне может стать веб-продуктом

Если ты делаешь веб-продукт похожей семантики — вот компоненты, которые ложатся напрямую:

### A. Структурированный capture эмоций / событий
- Голосовой ввод + LLM-структурирование в фиксированный шаблон
- Автоматическая категоризация по фиксированному набору осей (у нас 8, у тебя может быть N)
- Самообучающиеся правила категоризации

### B. Двойной слой шаблона
- Свободный ввод (нарратив) + структурированные таблицы (числа)
- Эмоция как объект с 7 полями (интенсивность, триггер, тело, корни, урок, что сделал)

### C. Иерархия трекеров
- Ежедневный (7 столбцов недели)
- Еженедельный (7 недель)
- Ежемесячный (7 месяцев)
- Архивы с реальными данными

### D. Многоуровневая аналитика
- День → неделя → месяц
- На каждом уровне — TL;DR (3 строки) + дашборд + нарративы + советы
- Сравнения соседних периодов

### E. Wheel-of-balance паттерн
- N-ось радар с трендами через периоды
- Прогресс-бары + численные оценки + текстовое обоснование

### F. Coaching tip как объект
- Наблюдение (с цитатой-доказательством)
- Эксперимент (конкретное действие)
- Метрика (измеримая, что считается успехом)

### G. Трассируемость данных
- Каждая цифра в дашборде кликабельна → раскрывает источник (день, цитата)
- Запрет на цифры без источника

### H. Анти-психологизация
- AI не интерпретирует, а структурирует
- Пользователь сохраняет авторство своих выводов
- Этот принцип — продуктовая дифференциация от обычных «AI-психологов»

### I. Учёт привычек со streaks
- Не просто %, а последовательности (`✓✓✗✓` → max streak / max gap)
- Архивы периодов с реальными данными

### J. Эмоциональный ландшафт периода
- Пики ≥8 как отдельная категория (важнее частоты)
- Позитив vs негатив по дням
- Сквозные триггеры (повторение через 2+ периода)

### K. Сквозные нарративы
- Темы, проходящие через несколько периодов, с аркой
- Не «недельные темы», а «месячные арки»

## 10. Что НЕ ложится на веб-продукт напрямую

- **Соционика как онтология** — это конкретный фреймворк одного пользователя; в массовом продукте может быть «8 сфер жизни», «12 архетипов», «пирамида Маслоу» и т.п.
- **Локальное хранение в markdown** — для веб-продукта нужна БД и облако
- **Obsidian как UI** — нужен собственный фронтенд
- **Git как механизм синхронизации** — для конечного пользователя избыточно
- **Глубина духовно-психологической терминологии** (внутренний мужчина, родовые программы, архангелы) — это специфика именно духовного психолога; для массы нужен более универсальный язык
- **Manual AI invocation** — пользователь сам инициирует анализ; в продукте логично делать автоматику и push-уведомления

## 11. Возможные точки интеграции

Если веб-продукт уже есть, можно протестировать совмещение через:

1. **Импорт markdown-логов** — формат `templates/template.md` достаточно прост, чтобы парсить
2. **Совместимость с Obsidian** — оставить пользователю возможность редактировать в Obsidian, продукт читает vault и строит аналитику
3. **API для AI-агентов** — продукт даёт endpoint, AI пользователя пушит логи туда
4. **Дашборд как embeddable widget** — `dashboard.html` адаптировать в iframe или React-компонент
5. **Обмен learnings.md** — переиспользуемая база правил категоризации между пользователями (с приватностью)
