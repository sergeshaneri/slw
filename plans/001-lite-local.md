## Целевой результат и принятые границы

Ветка `codex/lite-local` содержит временную статическую версию игры: полный доступ к существующим учебным материалам без регистрации, интерактивные путешествия и анкеты, локальные дневник и прогресс, отсутствие обращений к игровому API, явные заглушки для серверных функций.

Под «локальной памятью» принято `localStorage`: данные переживают перезагрузку в том же браузере и origin. React state обслуживает текущий интерфейс. При недоступности постоянного хранилища игра продолжает работать в памяти с сообщением, что данные исчезнут после закрытия. Полный offline/PWA не входит в задачу. Загружаются статические ресурсы сайта; требование об отсутствии логов относится к игровому бэкенду. Журналы статического хостинга регулируются его настройками.

«Все материалы» означает контент, уже подключённый к приложению: восемь аспектов, уровни путешествий L0–L3, теорию, упражнения, анкеты, описания навыков и психических черт, справочные блоки. Черновики исследовательских папок автоматически не публиковать. Материалы пользователей, находящиеся только в остановленной БД, недоступны без её восстановления. Недописанный материал обозначать как отсутствующий; не придумывать его при снятии блокировок.

## Архитектурное решение

Рекомендуется отдельная ветка с единым явным режимом lite-local. В ней lite — безопасное значение по умолчанию, включая обычный `npm run build`. Возможности: локальное сохранение, полный доступ к чтению, выключенные backend/auth. Переключатель не хранить в URL или localStorage. Сохранить online-путь там, где это допускает ограниченную правку; возврат полной версии — публикация исходной ветки.

Вариант «devAdmin всем и пустой API URL» отклонён: административные элементы становятся доступны, ограничения навыков снимаются не полностью, API-запросы сохраняются. Полная копия приложения увеличивает объём поддержки. Универсальный mock-сервер не нужен: имитация успешной отправки вводит пользователя в заблуждение.

### 2. Локальный запуск и блокировка транспорта

Создать единый runtime-режим: localPersistence/fullContentAccess=true, backendEnabled/authEnabled=false. Не подставлять фиктивного пользователя: appUser=null и isAdmin=false.

useAuth завершает lite-инициализацию до применения slw_token, URL-токена и tgAuthResult. App не интерпретирует auth/reset/referral/public-profile deeplinks как online-действия. Проверить фактические имена параметров, убрать auth-параметры из адреса через replaceState без очистки старого account-хранилища.

В main монтировать lite без ожидания bootstrapTMA; в самой bootstrapTMA поставить ранний запрет. В index.html не загружать Telegram SDK в lite, если интеграция не используется; обычный сайт должен открываться в Telegram webview без авторизации. Сбой внешних шрифтов не мешает игре; полный offline не обещать.

В request добавить защиту до getToken/fetch: типизированная локальная BackendUnavailableError при отключённом API. Отдельно закрыть прямой fetch downloadVaultZip. В вызывающих компонентах отключить обращения раньше защиты: нормальное использование не должно порождать её ошибки. В awardXP убрать отправку postStepCompleted для lite, в обработчике упражнения — chooseHabit, сохранив pendingTasks. Tracking рефералов и поддержка через API тоже отключены.

Проверка: `npm.cmd run typecheck` → exit 0. `rg -n 'fetch\(|sendBeacon|WebSocket|EventSource|XMLHttpRequest' src` → каждый транспорт перечислен и защищён. После добавления браузерных тестов — ноль API-попыток даже со старым токеном и непустым VITE_API_URL.

### 3. Изолированное локальное хранилище

liteStorage использует slw_lite_v1_journey, slw_lite_v1_scores, slw_lite_v1_diary, slw_lite_v1_history и отдельные lite-ключи подсказок/настроек. Формы данных сохранить. JSON parse и получение/использование localStorage обернуть в try/catch; обработать QuotaExceededError/SecurityError. При сбое сохранения не выдавать подтверждение постоянной записи.

Все lite load/save направить сюда. Не запускать loadFromApi, server save queue, guest migration и bot-events. Автоматически не копировать whl_*: они принадлежат предыдущему режиму. Не читать токены для экспорта.

Добавить экспорт `{ format: 'slw-lite', version: 1, exportedAt, data }`. Импорт полностью валидирует файл до изменения данных, показывает подтверждение замены, сохраняет прежнее состояние для отката. Ошибка записи не оставляет частично импортированный прогресс. Новую/неизвестную версию отклонять. Сброс удаляет только точный список lite-ключей. При событии storage из другой вкладки уведомить об изменении и предложить перечитать состояние перед следующей записью; сложный merge не нужен.

Проверка: typecheck и будущие storage-тесты: reload, недоступное хранилище, битый JSON, экспорт/импорт, отклонение и откат импорта, сохранность whl_*/slw_token. Schema version независим от CONTENT_VERSION.

Чистые проверки хранения допустимы через browser evaluate/вынесенные функции; тестировать пользовательские результаты и данные, не только повторять реализацию.

Network-suite перехватывает запросы до загрузки страницы, прерывает API и падает при любой попытке. Проверять /api/* на любом origin и настроенный API origin на любом пути. Сценарии: startup, чтение, ответы, сохранения, заглушки, ошибочные deeplinks, TMA initData, старые auth/devadmin-ключи. Использовать фиктивные токены. После навигации наблюдать период дольше максимального найденного polling/retry. Загрузка статической страницы допускается.

Content-suite сопоставляет фактические реестры с достижимым UI-контентом на нулевом прогрессе. Storage-suite проверяет reload, Unicode/длинные записи, удаление дневника, задания, импорт/экспорт, защиту старых ключей и отказ хранилища. Navigation-suite проверяет back, главную, каталог, восемь аспектов и все недоступные функции.

Команды из фронтенда после добавления тестов:

```powershell
npm.cmd run typecheck
npm.cmd run build
npm.cmd run test:lite:list
npm.cmd run test:lite
npm.cmd run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

Первые четыре — exit 0, непустой список тестов, все сценарии проходят. Preview — длительная команда ручной проверки http://127.0.0.1:4173/slw/. Playwright webServer сам запускает preview на отдельном свободном порту, чтобы не конфликтовать с ручным сервером. Если браузера Playwright нет, установить его явно и записать требования в README.

Повторить network-suite для сборки с непустым VITE_API_URL: старый production URL не должен активировать транспорт. Секреты/.env не выводить. Проверить итоговый diff: авторский контент и backend не изменены.

## Публикация и возврат

Ветка разработки не определяет URL GitHub Pages. Текущий deploy пишет dist в gh-pages и может заменить действующий сайт. В рамках реализации не запускать npm run deploy.

После приёмки выбрать цель: существующий /slw/ или отдельный сайт. Для прежнего адреса сохранить base; для нового согласовать base и проверить ресурсы. Перед заменой зафиксировать опубликованный commit/артефакт gh-pages. Публикация только по отдельному указанию. Backend и его ветку автоматического деплоя не менять.

Возврат полной версии — публикация проверенной сборки исходной ветки либо сохранённого артефакта. Lite-ключи остаются, online-код их не мигрирует. Перенос lite-прогресса на сервер — отдельная задача с явным согласием и проверкой формата. JSON-экспорт сохраняет возможность переноса между origin/браузерами.

## Критерии готовности

- [ ] Реализация в codex/lite-local; исходная ветка сохранена.
- [ ] Typecheck, build, test:lite — exit 0; тесты действительно выполняются.
- [ ] Ровно 0 попыток API во всех network-сценариях, включая шаги игры и старый токен.
- [ ] Чистый посетитель открывает все существующие учебные материалы без входа/предварительного прохождения.
- [ ] Чтение не меняет оценки, passes, completedScripts, XP.
- [ ] Ответы, дневник, задания и реальный прогресс переживают reload.
- [ ] Экспорт/импорт проверен; ошибки не уничтожают прежние данные.
- [ ] Старые whl_*, slw_token и account-ключи не меняются/не отправляются.
- [ ] Заглушки не подтверждают фиктивный успех; сетевые компоненты не монтируются.
- [ ] Backend, авторские тексты и посторонние файлы не изменены.
- [ ] Публикации до отдельного указания нет; README описывает хранение и возврат.

## Условия остановки и границы аудита

Остановить зависимый этап и сообщить причину, если изменилась Git-база, ветка уже содержит чужую реализацию, обязательный материал существует только на сервере или обнаружен неучтённый транспорт. После двух неудачных попыток исправления одного этапа зафиксировать blocker и результаты, не ослаблять критерии. Отсутствие браузерного runtime означает непроверенный пункт.

Проверены frontend-зависимости от API, правила доступа, локальное состояние и конфигурация сборки. Полный security-аудит backend, состояние хостинга/БД, браузерная работа, семантическая полнота каждого текста и размер/скорость сборки не проверялись. Уменьшение bundle не гарантируется отключением API; оптимизация загрузки — отдельная работа при измеренной необходимости.
