# SLW vault sync — мост между Obsidian-vault'ом и веб-приложением

Если ты ведёшь дневник локально в `SLW-Mine` (или другом Obsidian-vault той же
структуры), этот скрипт даст двустороннюю синхронизацию с веб-БД на Railway.

## Что синхронизируется

| Что в vault'е | Куда в БД |
|---|---|
| `diary/04.24 пт.md` или `2026-04-24.md` | `web_diary_entries` (raw text + структурированные `extra`) |
| Эмоции из таблиц дневника | `emotions` (отдельная таблица) |
| Тренировки из секции «Тренировки» | `trainings` (отдельная таблица) |
| `goals/БС-белая-сенсорика.md` и т.п. | `aspect_goals` (markdown целиком) |
| `analytics/29.03-05.04.md` | `analytics_reports` |
| `templates/template.md` | `web_users.diary_template` |
| `skills/skb-coach-skill/learnings.md` | `web_users.categorization_rules` (используется в промпте ИИ-коуча) |

## Установка

1. Python 3.9+ (у тебя уже есть для бэка)
2. `pip install requests`
3. Создай файл `tools/.env` рядом со скриптом:

```env
SLW_BACKEND=https://slw-production.up.railway.app
SLW_TOKEN=<JWT>
SLW_VAULT=/абсолютный/путь/к/SLW-Mine
SLW_YEAR=2026
```

**Где взять JWT:** открой web-приложение залогиненным, в DevTools → Application
→ Local Storage → найди ключ `slw_token`. Скопируй значение целиком.
Токен живёт 30 дней; при смене — обнови `.env`.

## Команды

```bash
# Проверить соединение и валидность токена
python tools/vault_sync.py status

# Сканировать vault и показать что нашлось (без отправки)
python tools/vault_sync.py import --dry-run

# Отправить весь vault на бэк (идемпотентно — можно гонять часто)
python tools/vault_sync.py import

# Что изменилось на бэке с момента указанной даты
python tools/vault_sync.py diff --since 2026-04-20T00:00:00

# Скачать всё с бэка в vault (ZIP → распаковка)
python tools/vault_sync.py export

# Скачать в отдельную папку, не перезаписывая существующие файлы
python tools/vault_sync.py export --target /tmp/slw-backup --merge
```

## Conflict-protocol

Если на бэке за время с последней синхронизации появилась/изменилась запись
дневника на ту же дату, что и в локальном vault — скрипт **не трогает** БД для
этой даты, а пишет обе версии в `<vault>/conflicts/<date>-<ts>.md`. Юзер
разруливает руками (читает обе версии, мерджит, удаляет конфликт-файл).

## Что парсится из markdown

**Дневник:**
- Raw text целиком — попадает в `web_diary_entries.text`
- Метаданные (`энергия: 7`, `сон: 8 часов`, `кофе: 2`) → `web_diary_entries.extra`
- Эмоции (таблицы вида «Эмоция / Интенсивность / Триггер / …») → отдельная таблица `emotions`
- Тренировки (`- присед 3×10×60`) → отдельная таблица `trainings`

**Цели:**
- Имя файла должно начинаться с кода аспекта (`БС-белая-сенсорика.md`, `ЧИ.md`).
- Контент идёт в БД целиком как markdown — на бэке/фронте отрисовывается «как есть».

**Аналитика:**
- Имя файла: `29.03-05.04.md` (неделя) или `Месяц 29.03-24.04.md` (месяц).
- Год берётся из `SLW_YEAR` в `.env`.
- Один файл = одна запись `analytics_reports`. Идемпотентно по
  `(user, type, period_start, period_end)`.

**Если паттерн не распознан** (странное имя файла, нестандартная структура
таблицы) — скрипт пропускает и пишет варнинг в stdout. Сырой текст всегда
попадает в `web_diary_entries.text`, даже если эмоции не распознаны.

## Идемпотентность

`import` можно гонять каждый день — повторный запуск с теми же файлами:
- если контент не менялся (одинаковый SHA1) → skip
- если менялся → update в БД
- ничего не дублируется

## Что **не** делает скрипт

- Не редактирует исходные файлы в vault'е (только читает).
- Не удаляет на бэке записи которые ты удалил в vault'е (это ручное действие).
- Не парсит `goals/tasks.md` целиком — это сложный файл с трекерами; пока его
  можно вынести вручную в нужные `user_habits` через веб-UI.
- Не следит за изменениями в реальном времени (TODO: режим `watch`).

## Что **на бэке** делается с присланным

См. `backend/app/web/routes/sync_vault.py` — там вся логика. Если нужно
изменить парсинг/маппинг — правь либо там, либо в `tools/vault_sync.py`
(парсер дублирован для автономности).
