# Архитектура SLW — проект на бумаге

Документ описывает, как построить полную версию приложения: коучинг-чат, БД прогресса, веб-оверview, ИИ-анализ дневника, социалка. Построен с учётом того, что MVP должен поехать за **3-4 недели**, а не за год.

Приоритет: **ship MVP → learn → extend**. Сначала работает самая узкая версия, затем к ней приклеиваем слои.

---

## 1. Что есть сейчас

- **Web-app** (React + Vite) — статический сайт, живёт в `slw-main/`. Данные хранятся в `window.storage` (localStorage-обёртка). Бэкенда нет.
- **Контент**:
  - `src/data/aspects.js` — краткие данные по 8 аспектам для web
  - `Si/Si_skills/` — 400 `.md` файлов: полная структура для БС (4 домена × навыки × 3 уровня × 4 файла)
  - `Si/level_0/ … level_3/` — материалы пользовательского трека (theory/exercises/questions/misc)
  - 13 больших `.md` в корне Si — исходники

**Проблема**: вся магия сидит в файлах, а юзер ею не пользуется. В приложении — только короткая выжимка aspects.js.

---

## 2. Скоуп MVP (то, что будет в первой версии)

**Входит:**
1. Telegram-бот, который ведёт пользователя по материалам **Уровня 0 Белой Сенсорики**.
2. Бот сохраняет ответы, прогресс, оценки в БД.
3. Текущий web-сайт **начинает читать** из той же БД и показывает: колесо (оценки из бота), прогресс (процент пройденного), последние записи дневника.
4. Минимальный дневник через бота: команда `/note <текст>` → запись в БД.

**Не входит (осознанно откладываем):**
- ИИ-анализ, ИИ-коуч, ИИ-классификация по аспектам
- Экспа/эссенс/ачивки (только счётчик «пройдено N из M»)
- Солнечная система, планеты, геймификация
- Социалка (друзья, пати, форумы)
- Остальные 7 аспектов (только БС в MVP)
- Web-редактирование (web = read-only)
- Поиск, закладки, напоминания

Это критично. Каждый откинутый пункт экономит неделю работы. Мы вернёмся к ним, когда MVP найдёт 20 живых юзеров.

## 3. Стек

| Слой            | Выбор                                                                    | Почему                                                                                                                                      |
| --------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Бот             | **Python 3.11 + `python-telegram-bot` v21**                              | Зрелый async framework, лучший в экосистеме. LLM-интеграции будут простыми.                                                                 |
| Веб-бэк         | **FastAPI + `asyncpg`**                                                  | Тот же Python, общие модели. Read-only API для web.                                                                                         |
| Фронт           | **React + Vite** (оставляем как есть)                                    | Переписывать нечего.                                                                                                                        |
| БД              | **PostgreSQL 16**                                                        | С первого дня. Postgres JSONB для гибкости, полнотекст, в будущем — pgvector для embeddings. SQLite не выбираем — мигрировать потом больно. |
| Миграции        | **Alembic**                                                              | Стандарт для SQLAlchemy.                                                                                                                    |
| ORM             | **SQLAlchemy 2.0 async**                                                 | Если без ORM — больно при росте.                                                                                                            |
| Auth (web)      | **Telegram Login Widget**                                                | Используем существующую Telegram-идентичность, не строим свою auth.                                                                         |
| Хостинг (MVP)   | **Railway** (или Fly.io)                                                 | Free tier, встроенный Postgres, git-based deploy. $0-5/мес.                                                                                 |
| Хостинг (позже) | VPS (Hetzner €4/мес)                                                     | Когда упрёмся в лимиты Railway.                                                                                                             |
| Контент         | `.md` файлы в репо → build-step парсит в JSON → бот грузит JSON в память | `.md` остаются source-of-truth, легко править вручную. В БД позже (admin-панель).                                                           |
| Логи            | Stdout → Railway UI (MVP) → Loki/Grafana (позже)                         | Без переинжиниринга.                                                                                                                        |
| Мониторинг      | Sentry (free tier)                                                       | Для раннего отлова багов бота.                                                                                                              |
| Env             | `.env` + `pydantic-settings`                                             | Типизированные настройки.                                                                                                                   |

**Альтернатива, которую я отклонил:**
- Node.js (grammy) — чтобы match React-стек. Но Python выиграл у ML/LLM-будущего и зрелостью бот-библиотек.
- Supabase вместо FastAPI — слишком много магии, сложно дебажить бота + БД когда они связаны логикой.

## 6. Границы сервисов

```
┌────────────────────┐          ┌────────────────────┐
│   Telegram API     │◄────────►│    bot service     │
└────────────────────┘          │ (python-telegram-  │
                                │    bot, FSM)       │
                                └─────────┬──────────┘
                                          │ SQL
                                          ▼
                                ┌────────────────────┐
                                │   PostgreSQL 16    │
                                └─────────┬──────────┘
                                          │ SQL
                                          ▼
┌────────────────────┐          ┌────────────────────┐
│   React web (SPA)  │◄────────►│   web backend      │
│   (slw-main)       │   HTTPS  │   (FastAPI)        │
└────────────────────┘          └────────────────────┘
```

**Ключевое правило:** бот и web **не разговаривают друг с другом напрямую.** Единственная точка связи — БД. Это позволяет:
- Деплоить их независимо
- Перезапускать бота без даунтайма web и наоборот
- В будущем — унести бот в отдельный процесс/контейнер

**Общий код** (модели SQLAlchemy, контент-loader) живёт в `backend/app/` и импортируется обоими сервисами.

## 7. Контент-пайплайн

Цель: `.md` файлы остаются источником истины, правятся руками в Obsidian, но бот не парсит их в runtime (медленно, ошибкоопасно).

```
Si/level_0/misc/02_welcome.md
         ▼
  build_content.py  (CLI, запускается вручную или CI-шагом)
         ▼
  backend/app/content/compiled.json  (коммитится в репо)
         ▼
  при старте бота / миграции:
  UPSERT в таблицу script_steps
```

**`compiled.json`** — массив `{id, aspect, level, ord, kind, title, body_md, meta}`. Команда `python -m app.content.build` перегенерирует его из `Si/`.

Это также заставит нас явно прописать «какой файл = какой тип шага». Пример маппинга для L0 БС:

| файл в Si/level_0/ | aspect | level | kind | title |
|---|---|---|---|---|
| `misc/01_planet_intro.md` | БС | 0 | info | Планета БС |
| `misc/02_welcome.md` | БС | 0 | info | Добро пожаловать |
| `misc/03_level_goal.md` | БС | 0 | info | Цель уровня |
| `theory/01_phenomenology.md` | БС | 0 | info | Что такое БС |
| `theory/02_key_questions.md` | БС | 0 | info | Ключевые вопросы |
| `theory/03_metaphors.md` | БС | 0 | info | Метафоры |

## 8. Поток бота (простой FSM)

```
IDLE
  /start ─► SHOW_WELCOME ─► ASK_BEGIN_BS ─► IN_SCRIPT(step=bs_L0_1)
                                                │
                                                ▼
                                        [info] ─────► next step
                                        [open_q] ─► wait for text ─► save answer ─► next
                                        [exercise_ack] ─► wait for button ─► save ack ─► next
                                        [score] ─► inline keyboard 1-10 ─► save score ─► next
                                                │
                                                ▼
                               последний шаг ─► LEVEL_DONE ─► unlock L1? (пока стоп)
```

**Команды-ескейпы** (работают в любом состоянии):
- `/note <текст>` — добавить запись в дневник
- `/progress` — показать прогресс по всем аспектам
- `/resume` — вернуться к текущему шагу
- `/menu` — главное меню

**Состояние диалога** хранится **в БД** (`user_state`), не в памяти процесса. Перезапуск бота — не теряет состояние.

## 9. Web после MVP

Минимальные изменения, чтобы web показывал реальные данные из бота:

1. `backend/app/web/routes/me.py`:
   - `GET /api/auth/telegram` — валидация Telegram Login widget, set cookie
   - `GET /api/me` → `{scores, progress_percent, last_diary_entries[5]}`
2. `slw-main/src/App.jsx`:
   - Убрать `window.storage`
   - Добавить `fetch('/api/me')` в `loadData()`
   - Показать кнопку «Войти через Telegram» если не залогинен
3. На web пока ничего нельзя менять — только читать. Это важно: вся запись идёт через бота.

## 10. Дорожная карта после MVP

Порядок фиксированный. Следующий шаг не начинаем, пока предыдущий не закрыт.

1. **MVP** (этот доc): бот L0 БС + read-only web. Цель — 5 человек прошли L0.
2. **Уровни 1-3 БС** — достроить шаги для L1/L2/L3 из существующих материалов.
3. **Остальные 7 аспектов уровня 0** — копируем паттерн.
4. **Экспа и прогресс-бар** — простой счётчик, видно юзеру.
5. **ИИ-анализ дневника** — OpenAI API, фоновая задача: классифицирует запись по аспекту (`diary_entries.aspect`). Кеш в БД, не пересчитываем.
6. **Ачивки** — `achievements` таблица оживает. Разовые unlock-события.
7. **Чат-коуч** — свободный диалог с ИИ, в промпт подгружается user profile (scores, recent answers). Rate-limit по стрику.
8. **Web-редактирование** — дневник, оценки можно менять из web.
9. **Социалка**: друзья → пати → форум. В этом порядке.
10. **Геймификация тяжёлая** — планеты, солнечная система, квесты. Только после того, как юзеры привыкнут заходить.

## 11. Риски и mitigation

| Риск | Mitigation |
|---|---|
| Тебе надоест до первой живой аудитории | Ограничь MVP до 3-4 недель. Если не успел — урезай скоуп ещё. |
| Стек незнакомый | Python+FastAPI — очень дружелюбные. AI-помощник по ним даёт 10/10. |
| Railway подорожает | Любой Python+Postgres переедет на VPS за день. |
| Telegram меняет API | Редко. `python-telegram-bot` обновляется первым. |
| ИИ сожжёт бюджет | Жёсткие лимиты на юзера (1 вызов/день по free, больше по стрику). Кеш в БД. |
| Юзеры не приходят | MVP должен быть опубликован и разослан 20 знакомым в день 1. Если никто не дошёл до L0 finish — проблема в контенте, а не в софте. |
